## Slides

- Front matter as in the module 01 sample ; `footer:` is the module name
- One slide per topic in the plan's module section. Port ARI510 slides where the
  course map says `from`, updated to the pinned stack ; write new ones for the rest
- Titles at most 40 characters, no `X: Y`. Bullets end lead-ins with ` :`. No bold,
  no em-dashes or en-dashes, no analogies, no rhetorical questions in bullets
- Code on slides is short, runs on the pinned stack, and matches the notebook
- Speaker notes in `<!-- NOTES: -->` : sources, skip marks (`Skippable.`), timing on
  the first slide of the module
- Pills : the slide a notebook section serves ends with `> \`demo04 · handoffs\`` for
  the first section and `> \`demo04b · handoffs-fixed\`` for later ones. Numbered
  pills ascend through the file ; each numbered pill appears once
- A `Summary : Module Name` slide closes the module

## Notebooks

- Generated by `build/make_moduleNN.py` with `build/nb.py` : `write_demo(module,
  slug, cells)`, `md`, `code`, `section("b · handoffs-fixed", "prose")`. The setup
  cell is added automatically and gives `llm`, `make_llm(**kw)`, `data(name)`,
  `data_folder(name)`, `make_embeddings()`
- Section headings are `section("a · slug", ...)`, `section("b · slug", ...)`, with
  kebab-case slugs. The first section's slide pill names the notebook slug
  (`demo04 · handoffs`), later pills the section slug (`demo04b · handoffs-fixed`).
  A notebook's sections sit on consecutive slides ; never put another notebook's pill
  between them. `src/slides/02-graph-fundamentals/` is a finished example
- One notebook per course-map row, one `section` per listed section, in order. The
  first markdown cell is `# Demo NN : Title` plus one line : run the cells in order
  and watch
- House style for demos : first person plural, one idea per markdown cell, rare
  comments, print results with short labels, never promise exact model output,
  close with an optional `Things to try`
- Demo data : `data/demo-world/` (Veenhaven Bus : `service.db` with depots,
  mechanics, buses, parts, work_orders ; `manuals/` ; `tickets.csv` ; `eval.jsonl`).
  Never use `data/capstone/` in a demo ; that is the exercises' world
- The course model is `llm`, `openai/gpt-6-luna` through OpenRouter with reasoning
  off. Use `make_llm(...)` for variants. Do not add other providers
- Stack : `langchain` 1.4.5, `langgraph` 1.2.15, `deepagents` 0.7.24. Check an API
  against the installed package (`uv run python -c "import inspect, ..."`) before
  you teach it. The docs move faster than the pin
- Handoffs between agent subgraphs : the documented example drops sibling tool
  results and the agent's earlier work. See `build/measurements.md` and
  `build/probe_patterns.py` for the faults and the fixes

## Running

```bash
uv run python build/make_moduleNN.py
COURSE_RPS=<your budget> uv run python build/run_notebook.py notebooks/NN-slug/*.ipynb
uv run python build/show_outputs.py notebooks/NN-slug/demo01-*.ipynb
bun run --cwd build lint
```

- Do not run `bun run --cwd build build` ; one PDF build at a time, done by the lead.
  If lint fails with `EBUSY` from puppeteer, another agent is linting : wait and retry

- The OpenRouter account allows 20 requests a minute for the whole team. Always set
  `COURSE_RPS` to the budget in your module brief. Never raise it, never loop on 429s
- Read every output after a run. A notebook that runs with a wrong or empty answer is
  not done. When a model result can go two ways, the prose says so
- Done means : every notebook executed with 0 errors and outputs read, lint passes
  for your file, every pill matches a notebook section and the reverse
